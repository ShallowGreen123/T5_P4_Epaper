# T5-P4 E-paper V0.3 模块测试计划

## 1. 文档目的

本文用于 T5-P4 E-paper V0.3 样板调试、硬件回归和小批量生产测试。测试依据为：

- `hardware/T5-P4 E-paper V0.3.PDF`
- `docs/pinmap_v0.3.md`
- 仓库 `examples` 下的独立测试程序

原则上先完成低风险、基础依赖项，再测试 EPD 高压、显示、音频、摄像头和 HDMI。任何基础电源或 I2C 身份检查未通过时，不进入依赖该模块的后续测试。

## 4. 测试前置条件

### 4.1 V0.3 软件映射

开始完整模块测试前，应先提供独立的 V0.3 board config，至少确认以下差异已经生效：

| 功能 | V0.3 映射 | 注意事项 |
| --- | --- | --- |
| 传感器中断 | GPIO6 | 不再作为 XL9555 中断 |
| 前光 PWM2 | GPIO52 | V0.2 使用 GPIO54 |
| ESP32-C6 复位 | GPIO54 直连 | V0.3 无 `C6_WAKEUP` 网络 |
| HDMI 复位 | XL9555 P00 | `HDMI_RST` |
| HDMI 电源 | XL9555 P01 | `HDMI_PWR_EN` |
| 触摸复位 | XL9555 P02 | `T_RST` |
| SD 电源 | XL9555 P03 | `SD_VDD_EN` |
| 音频功放 | XL9555 P04 | `AUDIO_EN`，V0.3 无 `AUDIO_SEL` |

当前根目录说明、V0.2 pinmap 和部分示例仍使用旧映射。涉及 XL9555、前光或 C6 控制的测试程序必须先确认其源码已经适配 V0.3。

### 4.2 安全停止条件

出现以下任一情况时立即断电并停止测试：

- 芯片、连接器、电感或电池异常发热、异味或可见损伤
- 输入电流明显超过限流设定，或主电源轨短路
- EPD `PWR_GOOD` 未通过，但程序仍尝试输出刷新波形
- EPD 正负高压幅值、极性或上下电顺序异常
- 同一 I2C 地址有多个器件同时响应

不得通过忽略 `PWR_GOOD`、强制刷新或取消超时来绕过 EPD 电源故障。

## 6. 分模块测试项目

### T01 外观、短路和基础电源

测试步骤：

1. 断电检查器件方向、缺件、连锡、虚焊、连接器和 FPC 座。
2. 测量 `VSYS`、主 3.3 V、1.8 V 等电源对地阻值，与正常样板对比。
3. 使用限流电源首次上电，记录关机、启动和稳定运行电流。
4. 分别验证 USB 供电、电池供电和 USB+电池供电。

通过标准：无短路、无异常发热；各基础电源幅值稳定；切换供电来源时不出现反复复位。

### T02 启动、Flash、PSRAM 和串口

测试步骤：

1. 完成擦除、下载和串口监控。
2. 检查启动日志中的芯片版本、Flash 容量和 PSRAM 容量。
3. 连续冷启动和复位各 10 次。
4. 运行 PSRAM 分配/读写测试，覆盖内部 RAM 和外部 RAM 的主要分配路径。

通过标准：每次均能启动到 `app_main()`；Flash/PSRAM 容量符合 BOM；无持续 WDT 复位、异常崩溃或内存测试错误。

### T03 主 I2C 和器件身份

主总线为 `SDA=GPIO7`、`SCL=GPIO8`。先使用 `examples/i2c_tools` 扫描，再读取身份寄存器。按实装和上电状态，预期设备包括：

| 器件 | 预期地址 | 必须检查的身份/状态 |
| --- | --- | --- |
| ES8311 | `0x18` | 可读 codec 寄存器 |
| PCA9535 | `0x20` | 输入/输出/方向寄存器可读写 |
| XL9555 | `0x22` | 输入/输出/方向寄存器可读写 |
| SGM38121 | `0x28` | `CHIP_REV` 正常 |
| LT8912B | `0x48` | 上电后配置寄存器可读 |
| BQ27220 | `0x55` | 电压、SOC、状态可读 |
| GT911 | 通常 `0x5D` | 产品 ID 和坐标数据可读 |
| TPS651851 | `0x68` | `REVID(0x10)`；TPS651851 应为 `0x66` |
| ICM-20948 | 建议 `0x69` | `WHO_AM_I=0xEA` |
| 充电 IC | 预期 `0x6B` | 型号/状态寄存器符合实装 BOM |

V0.3 原理图对充电 IC 标注 `0x6B/0x68`，而 TPS651851 固定为 `0x68`。ICM-20948 的标准可选地址也包含 `0x68`。必须确认充电 IC 使用 `0x6B`、IMU 使用 `0x69`，不能与 TPS651851 同地址。

普通 I2C 扫描无法识别同地址的两个器件，因此不能只以“扫描到 `0x68`”判定通过。必须读取 TPS `REVID`、IMU `WHO_AM_I` 和充电 IC 身份/状态寄存器。TPS `REVID=0x00/0xFF` 判定失败。

通过标准：所有实装器件地址唯一、身份正确；100 次连续寄存器读取无超时、NACK 或数据异常。

### T04 PCA9535 和 XL9555 扩展 IO

PCA9535 测试：

- 检查 `0x20` 应答和方向寄存器。
- 逐项切换 `EP_OE`、`EP_MODE`、`TPS_PWRUP`、`VCOM_CTRL`、`TPS_WAKEUP`，用示波器确认实际引脚电平。
- 验证 `TPS_PWR_GOOD` 和 `TPS_INT` 输入变化能被正确读取。

XL9555 测试：

- 按 P00～P04 顺序验证 HDMI 复位、HDMI 电源、触摸复位、SD 电源和音频功放使能。
- 每次只切换一个输出，并确认输出寄存器回读和下游信号一致。
- 不对 V0.3 未连接的 P05～P17 执行功能判定。

通过标准：逻辑电平、方向和下游功能均与 V0.3 pinmap 一致；切换某一路不会误动作其他模块。

### T05 充电、电量计和电池路径

测试步骤：

1. 先在不启动 EPD 的程序中确认充电 IC 地址为 `0x6B`、BQ27220 为 `0x55`。
2. 记录仅电池、仅 USB、USB+电池三种状态下的 VBUS、VSYS、BAT 电压和电流方向。
3. 验证预充、恒流、恒压、充满、再充和拔插 USB 状态切换。
4. 检查电量计电压、平均电流、SOC、温度与仪表实测是否合理。
5. 执行低电量关机和插入 USB 恢复测试。

通过标准：充放电状态与实际电源连接一致；无反复进出 HIZ/OTG/充电状态；电量计趋势正确；器件不过热。

### T06 TPS651851 和 EPD 高压

使用已包含 TPS 身份和上电预检的 `examples/epd_test`。

测试步骤：

1. `TPS_WAKEUP` 拉高后至少等待 1.8 ms，再进行首次 I2C 访问。
2. 在任何 VCOM/ENABLE 写入前确认 `REVID=0x66`；兼容 TPS65185x 版本可记录为 `0x45/0x55/0x65`，但必须与 BOM 一致。
3. 确认 VCOM 值来自当前面板标签或批次参数，不能只沿用其他屏的默认值。
4. 观察 `TPS_PWRUP`、`PWR_GOOD`、`VCOM_CTRL` 和 `EP_OE` 的上电顺序。
5. 测量 VPOS、VNEG、VDDH、VEE 和 VCOM，确认极性、幅值、纹波和稳定时间。
6. 断电时确认先关闭 EPD 输出和 VCOM，再关闭高压，并等待电源轨完成放电。

通过标准：TPS 身份正确；四路面板电源 `PG` 位全部就绪；PCA `TPS_PWR_GOOD` 与 TPS 寄存器状态一致；失败时程序只超时一次并停止刷新。

### T07 EPD 显示质量和前光

EPD 显示测试：

- 显示全白、全黑、棋盘格、水平/垂直线、文字和 16 级灰阶。
- 检查方向、镜像、缺线、坏点、灰阶、残影和边缘完整性。
- 分别执行全刷和局刷，记录刷新时间和电源峰值电流。
- 连续刷新至少 100 次，观察卡顿、超时、WDT 和画质退化。

前光测试：

- `LED_PWM1=GPIO53`、`LED_PWM2=GPIO52`，分别测试关闭、25%、50%、100% 占空比。
- 两路单独和同时点亮，检查亮度范围、均匀性、频闪、电流和温升。

通过标准：图像完整且方向正确；刷新耗时稳定；无电源故障；两路前光独立可控且无明显闪烁或异常温升。

### T08 GT911 触摸

测试前确认复位已改为 `XL9555 P02`。

测试步骤：

1. 读取 GT911 产品 ID 并完成复位/地址选择流程。
2. 使用 `examples/epd_touch_test` 检查四角、中心和边缘坐标。
3. 检查坐标方向、镜像、抖动、连续滑动和多点触控。
4. 重复冷启动，确认每次均能稳定识别触摸控制器。

通过标准：触摸点与显示位置一致；边缘无明显死区；无持续跳点或丢触；复位不会影响其他 XL9555 输出。

### T09 microSD

测试前确认 `XL9555 P03=SD_VDD_EN` 已拉到正确有效电平。SPI 引脚为 `MISO=44`、`SCK=45`、`MOSI=46`、`CS=47`。

测试步骤：

1. 使用 `examples/sd_card_test` 完成识别、挂载和容量读取。
2. 执行文件写入、读回和校验。
3. 记录顺序读写速度，并使用不同 SD 卡复测。
4. 执行 100 次挂载/卸载和上电识别测试。

通过标准：文件校验一致；无随机挂载失败；速度稳定且无持续 CRC/超时错误；SD 电源关闭后卡槽不反向供电。

### T10 ES8311、麦克风和扬声器

V0.3 音频引脚为 `MCLK=43`、`BCLK=42`、`LRCK=40`、`ASDOUT=41`、`DSDIN=39`，功放使能为 `XL9555 P04`。

测试步骤：

1. 确认 ES8311 在 `0x18` 正常应答。
2. 修正示例中旧的 PCA9535 功放使能映射，使用 XL9555 P04。
3. 使用 `examples/es8311_mic_speak` 执行麦克风到扬声器回环。
4. 测试静音、音量、麦克风增益和多个采样率。
5. 分别检查录音、播放、底噪、爆音、左右/单声道配置和持续运行温升。

通过标准：录放音连续，无 I2S underrun/timeout；功放开关有效；静音时无明显爆音；声音无严重失真。

### T11 ESP32-C6、SDIO 和 Wi-Fi

V0.3 使用 SDIO `D0～D3=GPIO14～17`、`CLK=18`、`CMD=19`，C6 复位为 ESP32-P4 `GPIO54` 直连。

测试步骤：

1. 给 C6 下载与主机组件匹配的 `esp-hosted` slave 固件。
2. 验证 GPIO54 可可靠复位 C6，且软件不再访问旧 XL9555 C6 控制位。
3. 使用 `examples/c6_wifi_scan` 连续扫描至少 10 次。
4. 记录 AP 数量、RSSI 和 SDIO 错误计数，并执行 30 分钟持续通信。

通过标准：C6 每次均能复位并完成 hosted 握手；Wi-Fi 扫描结果合理；无 SDIO CRC、超时或持续重连。

### T12 ICM-20948

测试步骤：

1. 确认地址跳线使 IMU 工作在 `0x69`，避免占用 TPS651851 的 `0x68`。
2. 使用 `examples/icm20948` 检查 `WHO_AM_I=0xEA` 和 AK09916 ID。
3. 静止时检查加速度模长约为 1 g，转动板卡观察三轴变化。
4. 检查陀螺仪零偏、磁力计变化、温度和 GPIO6 `SEN_IRQ`。

通过标准：身份正确；四类数据连续且方向合理；中断可达 GPIO6；不会影响 TPS651851 通信。

### T13 SGM38121 和 MIPI 摄像头

测试步骤：

1. 使用 `examples/sgm38121` 读取 `CHIP_REV`，先以只读模式检查寄存器。
2. 启用相机电源后测量 1.8 V、2.8 V 等目标电源轨。
3. 使用 `examples/camera_id_detect` 读取摄像头 ID。
4. 使用 `examples/camera_wifi_stream` 检查分辨率、帧率、画面方向和连续传输。
5. 执行摄像头反复上电 20 次和 30 分钟持续预览。

通过标准：电源轨幅值和时序正确；传感器 ID 与实装型号一致；图像无持续花屏、丢帧或 MIPI 错误。

### T14 HDMI/LT8912B

测试前确认 `XL9555 P01` 控制 HDMI 电源、P00 控制复位；`HDMI_INT=GPIO4`，DDC 使用 GPIO9/10。

测试步骤：

1. 测量 HDMI 1.8 V 电源并检查 LT8912B 复位波形。
2. 读取 LT8912B 配置寄存器和显示器 EDID。
3. 使用 `examples/hdmi_video_renderer` 播放 SD 卡视频。
4. 测试冷启动、热插拔、拔插 HDMI 和 30 分钟连续播放。

通过标准：显示器稳定锁定；画面尺寸、色彩和方向正确；热插拔后可恢复；无持续黑屏、闪屏或解码卡顿。

### T15 USB Host/Device

USB OTG 数据引脚为 `DM=GPIO49`、`DP=GPIO50`。

测试项目：

- Host HID：使用 `examples/usb_host_hid_basic` 测试键盘、鼠标和 Hub。
- Host MSC：使用 `examples/usb_host_msc_example` 测试 U 盘枚举和文件读写。
- Host Camera：使用 `examples/usb_host_hub_dual_camera` 测试 Hub 和 UVC 摄像头。
- Device MSC：使用 `examples/usb_device_msc_wireless_disk` 测试主机枚举和存储访问。
- Device UAC：使用 `examples/usb_device_uac` 测试扬声器、麦克风、音量和静音。

通过标准：Host/Device 模式均能稳定枚举；数据传输无异常断开；VBUS 方向和电流能力符合设计；音频/存储数据正确。

### T16 J2 扩展口和 BOOT 键

测试步骤：

1. 检查 J2 的 VSYS、GND 和各 GPIO 连通性、短路及丝印方向。
2. 对 GPIO51、50、2、49、11、23、12、22、20、21 执行高低电平和回环测试。
3. 验证 J2 上共享的 I2C GPIO7/8 和 SPI GPIO44/45/46 不影响板载器件。
4. 验证 GPIO35 BOOT 键按下/释放电平和下载模式。

通过标准：所有引脚与 V0.3 pinmap 一致；输入输出电平可靠；共享总线无争用；BOOT 键功能正常。

### T17 Factory 综合回归和老化

必须在 `examples/factory` 完成 V0.3 board config 适配后再执行。

测试步骤：

1. 依次进入电池、SD、音频、摄像头、HDMI、Wi-Fi、EPD 和触摸页面。
2. 在模块切换过程中检查资源释放、重复初始化和电源状态恢复。
3. 执行至少 2 小时综合老化，包括 EPD 周期刷新、Wi-Fi 扫描、音频、SD 读写和外设反复开关。
4. 记录最大电流、关键器件温度、内存余量、WDT、异常复位和错误日志。

通过标准：所有独立测试已通过；综合切换无冲突；老化期间无崩溃、WDT、异常复位、内存持续下降或器件过热。

## 9. 验收规则

- P0 项目必须全部 PASS；任一 P0 FAIL 时整板不通过。
- 未实装的可选模块可以标记 NA，但必须记录 BOM 依据。
- P1 项目按产品 SKU 要求全部 PASS；P2 项目按接口交付范围执行。
- 修复硬件、BOM、pinmap、供电时序或共享总线问题后，除重测失败项外，还应回归其所有上游依赖和下游模块。
- 每项 FAIL 必须保存完整串口日志、供电条件、固件 commit、关键波形或测量值，不能只记录现象描述。
